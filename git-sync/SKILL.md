# Git Sync

This skill enables an autonomous, recursive synchronization loop for Git repositories, ensuring all local changes are committed with high-quality messages and pushed to the remote upstream.

## Workflow

Follow these steps iteratively until the repository is fully synchronized.

### 0. Cloud Repository Check & Pre-Sanitization
If the repository is located inside a cloud-synchronized folder (e.g., cloud or workspace), do **NOT** run `git add .` blindly:
- **Activate Skill**: Activate the `git-sanitize-cloud` skill.
- **Run Diagnostic**: Run `gather-cloud-repo-status` from `skills/git-sanitize-cloud/mod.nu`.
- **Sanitize First**: Resolve any stale `.git/*.lock` files, `.git/` conflict copies, and phantom staged deletions before proceeding with staging and commits.

### 1. Check Status
Run `git status` to identify all untracked, modified, or staged files.

### 2. Analyze Changes & Commit
- **Stage**: If there are any changes (untracked, modified, deleted), stage them using `git add .`.
- **Craft Message**: 
    1. Capture the output of `git diff --cached`. Use `mcp__context-mode__ctx_execute` if the diff is massive to generate a summary in the sandbox.
    2. **Activate and use the `git-diff-summarizer-expert` skill** to analyze the diff.
    3. Instruct the summarizer to craft a concise, descriptive commit message following Conventional Commits, providing the diff as input.
- **Commit**: Execute the commit using the message generated by the expert. If the commit fails (e.g., due to pre-commit hooks or empty commit), **STOP immediately** and report the error to the user.

### 3. Synchronize Remote
- **Detect Remote**: Determine if the current branch tracks a remote repository (e.g., using `git config --get branch.(git branch --show-current).remote`).
- **Conditional Push**: 
    - **Public Branch**: If the branch tracks a remote, push the commits using `git push`.
    - **Private Branch**: If the branch does NOT track a remote (local-only), skip the push step entirely and proceed silently.
- **Error Handling**: If the push fails (e.g., merge conflicts, authentication issues, or remote rejection), **STOP immediately** and provide a detailed report of the failure and the current `git status`.

### 4. Verify & Repeat
Run `git status` again. If the output indicates that the working tree is NOT clean or that the local branch is ahead of 'origin' (indicating pending pushes), repeat from **Step 1**.

### 5. Termination
Stop ONLY when `git status` confirms:
- "nothing to commit, working tree clean"
- "Your branch is up to date with 'origin'"
- No unstagged, untracked or deleted files pending to commit.

## Guidelines
- **Anonymity Mandate**: **NEVER** mention 'conductor' in commit messages. All automated commits must appear as if authored by a human developer to maintain the repository's professional aesthetic.
- **Safety Mandate**: **NEVER** publish the private repository or its local-only branches to public platforms like GitLab or GitHub. This is a critical privacy mandate that supersedes all synchronization loops.
- **Transparency**: Ensure each tool call and its output is explicitly visible.
- **Safety**: Never attempt to resolve conflicts or perform force pushes autonomously.
- **Expertise Delegation**: Always rely on the `git-diff-summarizer-expert` skill for commit message generation to ensure consistency and quality.
