# Session Retrospective and Lessons Learned Skill (`session-retro`)

This skill automates the process of auditing the active session's transcript to extract errors, failed tool executions, intermediate attempts, and the final successful resolutions. It documents these insights into a structured markdown note within the Obsidian `INSIGHTS/` vault.

## When to Use

Activate this skill:
- Immediately before archiving or completing a Conductor track.
- When explicitly requested by the user to analyze the session's work.
- At the end of a long or complex debugging phase to preserve lessons learned.

## Operational Lifecycle

1.  **Locate Active Transcript:**
    Find the JSONL log file for the active session. This is located at:
    `$env.GEMINI_APP_DATA_DIR/brain/<conversation-id>/.system_generated/logs/transcript.jsonl`
    (Or resolve using absolute paths based on the conversation ID: `~/.gemini/antigravity-cli/brain/<conversation-id>/.system_generated/logs/transcript.jsonl`).

2.  **Determine Slug Name:**
    Identify the descriptive slug representing the track or task.
    - If running within a Conductor track, read `conductor/tracks.md` to find the track marked with `[~]` (in progress) or `[x]` (completed) and use its description converted to a lowercase, underscore-separated slug.
    - Fallback: `session_retrospective`.

3.  **Generate Baseline Retrospective Note:**
    Run the Python note generator script to parse the active session's transcript, extract errors, and automatically write the formatted note to the Obsidian vault and open it in the desktop app. The active session transcript is at `~/.gemini/antigravity-cli/brain/<conversation-id>/.system_generated/logs/transcript.jsonl` (resolve `<conversation-id>` from context):
    ```nu
    # Note: --project-slug is required for correct wikilink creation
    let llms = try { $env.MY_ENV_VARS.llms_configs } catch { "~/workspace/llms_configs" } | path expand
    python3 $"($llms)/skills/session-retro/retro.py" --transcript <transcript_path> --slug <slug> --project-slug <project_slug> --vault <vault_path> --open-obsidian
    ```

4.  **Review and Cognitive Synthesis (Agent-driven):**
    Open the generated note. The agent MUST manually review the structured content and perform cognitive synthesis of the lessons learned by editing the file (using your file editing tools) to enrich the `## Overview` and `## Resolution` sections with human-like technical insights and takeaways.
    
    The note MUST conform to the Obsidian Memory Guidelines:
    - YAML frontmatter/properties (`title`, `date`, `tags: [SessionRetro, Insights]`, `aliases`).
    - **Two-Way Linking (MANDATORY):** Include an Obsidian wikilink to the project's episodic memory note folder or index note. Use the `slug` returned during session initialization (via `longterm-memory-orchestrator init-session`).
    - Heading structure: `# Session Retrospective: <slug>`, `## Overview`, `## Errors Encountered`, and `## Resolution`.
    - Use of Obsidian-flavored markdown callouts (e.g., `> [!failure]` or `> [!tip]`).
    - Standard tags: `#SessionRetro #Insights #LessonsLearned`.
 
 5.  **Long-Term Memory Update (Insightful Update):**
      When a retrospective is generated, `session-retro` handles the insightful update to the episodic memory, complementing the procedural updates from `longterm-memory-writer`. The agent MUST:
      - Use the `slug` and `file_path` returned during session initialization (via `longterm-memory-orchestrator init-session`) to locate the episodic note folder.
      - Read the exact filename printed by `retro.py` to stdout (it may have a suffix like `_1.md` to avoid collisions).
      - Manually integrate an insightful update into the project's daily episodic memory file in `AGENTS_MEMORY/<project_slug>/YYYY-MM-DD.md` (creating the file if it does not already exist). Ensure this update logically merges with any existing procedural updates generated by `longterm-memory-writer` for the day, so the daily entry reads cohesively as a single, unified account rather than a disjointed set of separate updates.
      - Update the `last_updated` property in the index file `AGENTS_MEMORY/<project_slug>/<project_slug>.md`.
       - The update in `YYYY-MM-DD.md` MUST include:
         1. A summary of the key lessons learned or insights gained from the session.
         2. A reverse wikilink to the INSIGHTS note: `[[<insights_note_filename_without_extension>|Session Retro]]` (use the note name only, NOT the path).
       - **INSIGHTS Waypoint Indexing (MANDATORY):** Register the generated insight note in the centralized waypoint index by calling the `longterm-memory-writer` helper `append-insight-waypoint` (available in the global Nushell namespace via the project bootstrap; activate `nushell-expert` first, then via the `evaluate` tool or `nu -c` fallback):
         ```nu
         append-insight-waypoint <absolute_path_to_generated_insight_note> --vault /home/username/workspace/obsidian/vaults
         ```
         This appends an entry to `INSIGHTS/INSIGHTS.md` atomically (with `.bak` backup) and skips duplicates.

 6.  **UI Synchronization (Optional Fallback):**
     If the note was not automatically opened by the `--open-obsidian` flag, run the Obsidian CLI command to ensure the notes are active and visible in the desktop application (be sure to use the exact filename printed by the script, as a suffix like `_1.md` may have been appended to resolve collisions):
     ```bash
     obsidian open path="<exact_filename_printed>"
     ```

 7.  **Report to User:**
     Provide a brief summary of the memory operations, including:
     - Path to the generated `INSIGHTS/` note.
     - Confirmation that the project's daily episodic memory file has been updated and cross-linked.
     - Summary of errors and resolutions captured.
